# Rubric: 401

If the learner misses a question here, set a DEFINE or INTERPRET move for 401 live, as help (it is
recorded as helped and doesn't count), then come back to a production question.

401 is the status code for a request from someone not signed in: the server doesn't know who is
asking, so it refuses. Its official name is Unauthorized, which misleads, since it suggests signed
in but not allowed; that is 403. The word has no confusable listed, so both questions are CATCH,
and the first is aimed at the misreading of the name.

### q1

- **goal:** `w-401`
- **move:** CATCH
- **answer:** 401 is for a request from someone not signed in. This user is signed in, so the
  server knows who they are; they are just not allowed to delete this recipe, which calls for 403,
  not 401.
- **credit:** full for naming that 401 means the requester isn't signed in, and this one is, so it
  is the wrong code here. Half for "it should be 403" without saying what 401 means. None for a
  different quibble alone, such as that the Delete button should be hidden.
- **tutor note:** a learner who says "the name Unauthorized is misleading" has spotted the trap;
  ask what the code actually reports about the requester.

### q2

- **goal:** `w-401`
- **move:** CATCH
- **answer:** 401 is what a request from someone not signed in should get. The student signed out,
  so the server rightly refused; the 401 shows the rule is holding, not that sign-in is broken.
- **credit:** full for naming that 401 means the request came from someone not signed in, which is
  true here, so it is the right answer from the server. Half for "that's expected" without saying
  what 401 reports. None for a different quibble alone, such as that the path name is wrong.
