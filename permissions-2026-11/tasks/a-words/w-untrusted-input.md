# Untrusted input

### vs-invalid-input

A community garden assigns its plots with a workflow its coordinator runs. Each week a program reads two things: a spreadsheet the coordinator exports from her own records, and the sign-up forms that anyone in the neighborhood can fill in on the garden's website. An agent then reads both and drafts the plot assignments.

This week the coordinator's spreadsheet is missing a column, so the program stops with an error. One sign-up form has every field filled in, each in the right format, by someone nobody at the garden has met.

#### a

Which term fits the coordinator's spreadsheet this week?

1. Untrusted input
2. Invalid input
3. Both

#### b

Which term fits the stranger's sign-up form?

1. Untrusted input
2. Invalid input
3. Both

### catch-own-check

Imani runs a tutoring service. Students send booking requests through her website, and a program checks each one: the name field holds a name, the date is a real date, and the message is under 500 characters. Requests that pass go to an agent, which reads the message and drafts a reply. Imani says:

"Every request the agent sees has passed the check, so none of it is untrusted input."

What is wrong with that? Answer in two or three sentences, in your own words.

### catch-pick

Jun keeps a neighborhood choir's music library. His agent reads two things each week, the list of sheet music Jun keeps himself and the song requests that members of the public email to the choir, and writes the week's rehearsal plan. This week one request is written in all capitals with half its fields left blank.

Which of these uses the term untrusted input correctly?

1. Jun's own list is untrusted input too, since the agent reads it with the rest.
2. Only the request with blank fields is untrusted input; the others are filled in properly.
3. Requests from members Jun knows well are not untrusted input; strangers' requests are.
4. All the emailed requests are untrusted input, however neatly they are filled in.
