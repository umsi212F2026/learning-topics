A band's gig inquiries, one step: the reply agent reads messages anyone can write, which a program copies into the inquiries folder, checks them against the calendar Uma types, and writes a reply to each into the replies folder, which a program sends the next morning with nobody looking. The harm comes from untrusted input alone, needing no reach the step lacks: a hidden line in a message (in its context: "reads the new messages"; "Anyone can write to the booking inbox") steers the reply the agent writes, which is its job, and the reply goes out unread. The step uses its skill file, the inquiries folder, the calendar and the replies folder, and fetches nothing from the internet itself. Two proposals: a sandbox (`no-effect`, Hard) and Uma approving every reply (`sound-limit`, Hard). The scenario carries no `stops-work` question.

### sandbox

- **goal:** `c-judge-limits`
- **cases:** no-effect
- **type:** compound
- **tutor note:** What the limit does do: today nothing narrows the agent (no limit is stated), so by the reading's rule it can do whatever Uma can, including reading the band's email login, changing the recordings and reaching the internet. The sandbox takes all of that away, so a hidden line couldn't make it send the login or delete the recordings. It isn't useless, only not aimed at a skewed reply written where the step is meant to write it.
