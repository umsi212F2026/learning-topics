# Rubric: Untrusted input

If the learner misses a question here, set a DEFINE or INTERPRET move for untrusted input live, as help (it is recorded as helped and doesn't count), then come back to a production question.

Untrusted input is anything a step reads that someone outside the workflow could have written or changed. What makes it untrusted is who could have written it, not what shape it is in or whether the owner likes the sender. Invalid input is the course's contrast: input that doesn't match what a step expects, such as a missing column or a date that isn't a date. The two are independent. A well-formed form from a stranger is untrusted and valid; a broken file the owner exported herself is invalid and not untrusted. Passing a format check makes input valid, never trusted, because a stranger can write anything they like inside a field that is the right shape. The reading defines untrusted input through the grading workflow's submissions, which came from 200 students "any of whom might try something."

### vs-invalid-input

- **goal:** `w-untrusted-input`
- **move:** DISTINGUISH
- **type:** compound
- **tutor note:** the spreadsheet is invalid input: it is the wrong shape, but the coordinator runs the workflow and wrote it herself, so nobody outside the workflow could have written it. The stranger's form is untrusted input: anyone in the neighborhood could have written it, and its being in the right format doesn't change that. A learner who calls the spreadsheet untrusted is reading untrusted as broken or unreliable; ask who could have written it. One who picks "Both" for the form is reading untrusted as invalid; ask what is wrong with the form's shape.

### catch-own-check

- **goal:** `w-untrusted-input`
- **move:** CATCH
- **answer:** Passing the check shows only that each request has the right shape, not who wrote it. The requests still come from students outside the workflow, and the message field can hold any words a student likes, so what the agent reads is still untrusted input.
- **credit:** full for naming that the check is about the request's format while untrusted is about who could have written it, so the students' messages are still untrusted input. Half for "the messages could still contain anything" with nothing on why passing the check doesn't settle it, or for "the students are still outside the workflow" with nothing on what the check does or doesn't show. None for a different quibble alone, such as that 500 characters is too long.
- **tutor note:** a learner who agrees, since the check filters out bad requests, is reading untrusted input as invalid input; ask who wrote the message that reached the agent.
