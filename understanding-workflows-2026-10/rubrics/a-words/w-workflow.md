# Rubric: Workflow

If the learner misses a question here, set a DEFINE or INTERPRET move for workflow live, as help
(it is recorded as helped and doesn't count), then come back to a production question.

A workflow is a repeatable arrangement of steps, potentially done by more than one actor, with the
order of the steps and the handoffs settled before a run starts. Drop "repeatable" and it is a
project, done once. Drop the settled order and it is a checklist. A workflow is the steps, not
the result they reach.

### vs-project

- **goal:** `w-workflow`
- **move:** DISTINGUISH
- **answer:** Saturday intake is a workflow: it runs again and again, once per client, with the
  order and the handoffs (greeter to desk to shopper) settled before any run starts. The move is a
  project: it happens once, and its steps are being worked out during it rather than settled ahead.
- **credit:** full for naming either difference: that a workflow is repeated, run after run, while
  a project is done once, or that a workflow's order is settled in advance while the project's is
  worked out as it goes. Matching the pantry's two activities is not required, but any match given
  must be right, and a wrong one makes it half. None for an incidental difference alone, such as that the move is bigger, harder or more
  important.
- **tutor note:** a learner who says "a project has a deadline" has named something true but
  incidental; ask how many times the pantry will move, and how many clients it will register.

### catch-pick

- **goal:** `w-workflow`
- **move:** CATCH
- **type:** mcq
- **answer:** 3
- **credit:** full for 3 only. Casting is repeated for every show, its order is settled in advance,
  and it passes between actors (director, then whoever sends offers). Choice 1 is a project: it
  happens once and is planned as it goes. Choice 2 is a checklist: its items have no settled
  order. Choice 4 names an outcome the shows aim for, not an arrangement of steps that gets there.

### vs-checklist

- **goal:** `w-workflow`
- **move:** DISTINGUISH
- **answer:** Sending campers home is a workflow: its order is settled in advance (ID at the gate,
  then the office's check, then the counselor) and it passes from one actor to the next. The cabin
  list is a checklist: the items have to get done, but in no settled order. Both are repeated, so
  repetition is not what separates them.
- **credit:** full for naming that a workflow's order is settled before a run starts and a
  checklist's items have none; the handoffs between actors are welcome but not required. Half for
  naming only that the pickup involves several people and the cabin list one, with nothing on
  order, since a checklist can be split among people too. None for an incidental difference
  alone, such as that one is longer, or for "a workflow is repeated", which holds for both here.

### catch-garcia

- **goal:** `w-workflow`
- **move:** CATCH
- **answer:** The Garcia order is one run, not the workflow. The workflow is the arrangement every
  order follows (front desk, designer, press operator); what took four hours yesterday was one
  pass through it for one order.
- **credit:** full for naming that the Garcia order is a single run and the workflow is the
  arrangement every order follows. Half for "that's a run" with nothing on what the workflow is.
  None for a different quibble alone, such as that the jams are a printer problem rather than a
  workflow problem.
