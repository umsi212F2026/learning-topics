# Rubric: CLI

If the learner misses a question here, set a DEFINE or INTERPRET move for CLI live, as help (it is
recorded as helped and doesn't count), then come back to a production question.

A CLI is a program you, or your agent, drive by typing commands: a host's CLI is a program you
install, sign in to, and then type commands into a terminal to reach your app on the host, such
as to read its logs. "Command-line interface" and "command-line tool" are other names for it.
CLI has no nearest confusable in this topic, so its questions are CATCH only. Quillbay is a
made-up host.

### q1

- **goal:** `w-cli`
- **move:** CATCH
- **answer:** A CLI is driven by typed commands, and a coding agent can type and run commands in
  a terminal as well as edit files. So the agent can run Quillbay's CLI itself, such as to read
  the logs, once it is installed and signed in.
- **credit:** full for naming that a CLI is driven by commands and the agent can run commands,
  so it can use the CLI. Half for "the agent can use it" without saying why. None for a different
  quibble alone, such as that the student should use an MCP server instead, or that the agent
  shouldn't have access.

### q2

- **goal:** `w-cli`
- **move:** CATCH
- **answer:** The terminal is only where commands are typed. Quillbay's CLI is a separate
  program, made by Quillbay, that has to be installed (and signed in to) before its commands work
  in that terminal.
- **credit:** full for naming that the CLI is a program of its own that runs in the terminal, not
  the terminal itself, so it has to be installed. Half for "you do need to install it" without
  saying what the CLI is. None for a different quibble alone, such as that VS Code's terminal is
  not the only one, or that they also need to sign in.
