I keep the tip line running for our neighborhood watch. Neighbors text the watch's tip number
when they see something worth a look, like a broken streetlight or a car left running with no one
in it. A program on the watch's office computer texts each neighbor back with a tip number and
forwards the tip to the volunteer on duty, taking about a second for each. The office computer is
never turned off. Tips come a few an hour, well under the fifty a minute the program can handle.
Each neighbor who sends a tip is waiting to hear, within a minute or so, that it arrived. The watch
meets in the library basement on the second Tuesday of each month.

### q1

Where, if anywhere, should this workflow's work wait, and why?

1. Nowhere, each tip going straight to the program as it arrives, because nothing needs to wait, as the program is always available and never overloaded.
2. In a list the workflow keeps as each tip arrives, because a burst would arrive faster than the fifty a minute the program handles.
3. Nowhere, each tip going straight to the program as it arrives, because nothing needs to wait, as losing some tips does no harm here.
4. In a list the workflow keeps as each tip arrives, because tips sent while the office computer is off, each with a neighbor waiting, would never be handled.
