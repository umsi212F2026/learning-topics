# Rubric: Polling

If the learner misses a question here, set a DEFINE or INTERPRET move for polling live, as help
(it is recorded as helped and doesn't count), then come back to a production question.

Polling is asking again and again whether anything has changed, rather than being told. The asker
starts each look, usually on a schedule, and most looks find nothing. With a hook it is the other
way around: the tool or service where the change happens runs your command, or sends your address
a message, when it happens. Being slower and wasting looks are consequences of polling, not what
the word names. Polling does not have to be nonstop; checking every 15 minutes is polling.

### vs-hook

- **goal:** `w-polling`
- **move:** DISTINGUISH
- **answer:** Asking the shop every two minutes is polling. The web address the shop sends a
  message to is the hook.
- **credit:** full for both labels right: the program asking every two minutes is polling, and
  the shop's web-address setting is the hook. A reason is welcome but not required. Half for one
  right and the other missing. None for swapping the two, or for calling both the same thing.
- **tutor note:** a learner who swaps them may be reading "hook" as something the program hooks
  into to check; ask which way, in each, the news of an order travels.

### catch-pick

- **goal:** `w-polling`
- **move:** CATCH
- **type:** mcq
- **answer:** 1
- **credit:** full for 1 only. The script asks the sheet again and again whether there are new
  rows, and nothing tells it, so it is polling. Choice 2 reads polling as being told, which is
  what a hook does. Choice 3 reads polling as sending people messages, as in an opinion poll; the
  emails are what the script does after it finds a new row. Choice 4 holds the word too narrowly:
  asking every 15 minutes is still asking again and again.

### catch-build

- **goal:** `w-polling`
- **move:** CATCH
- **answer:** That isn't polling. The code site sends the build server a message each time someone
  pushes, so the server is being told, which is a hook (a webhook). Polling would be the build
  server asking the code site again and again whether there is a new change.
- **credit:** full for naming that the server is being told rather than asking, so this is not
  polling; naming it a hook or webhook is welcome but not required. Half for "that's a webhook"
  with nothing on why it isn't polling. None for a different quibble alone, such as that a build
  should not start on every push.
