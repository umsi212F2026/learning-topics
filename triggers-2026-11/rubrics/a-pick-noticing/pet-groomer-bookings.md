Shape `hook-best`, case `hook`. The natural method is a webhook: the website sends a notice each
time a booking arrives. The source can send word ("The website can send a message each time a
booking comes in"), receiving it is easy to set up on a machine that is never off ("Our computer
person can set up the shop computer, which is never turned off, to take in those messages in an
afternoon"), and the result is needed soon ("Each booking should be confirmed within a few minutes
of the owner making it"). Frequent checking is ruled out because each check is costly: "Each look
at the bookings means the agent reading through every booking again." The neutral sentence is "The
confirmation is a short note with a paw print that our youngest groomer drew." Two webhook, two
polling.

### q1

- **goal:** `c-choose-noticing`
- **cases:** hook
- **type:** mcq
- **answer:** 3
- **credit:** full for 3 only; none for the others.
- **tutor note:** Sound (3): the website can send a message each time a booking comes in, and the
  computer person can set up the always-on shop computer to take those messages in, so each
  booking arrives as it is made; that is what separates a webhook from polling here. 1 is the other
  method, checking slowly to keep checks few: each look does mean the agent reading through every
  booking again, but an hourly poll leaves bookings waiting far past the few minutes they should be
  confirmed within. 4 is the other method, checking often enough to be timely: bookings should be
  confirmed within a few minutes, but a look every minute means the agent reading through every
  booking again, every minute. 2 is not a difference: the paw print bears on nothing about how new
  bookings are found. If the learner picks 4, ask what each of those looks costs.
