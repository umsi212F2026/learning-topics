Accepted: an event, each new message through the contact form starting a run. Cheap repeated looks
at the form that start the agent only when a message is new ("a program glances at the form every
few minutes and starts the agent only when something has come in") are this same choice, whatever
the answer calls them.

The deciding facts, and the sentences carrying them:

- How soon the result is needed: "Someone writing about a broken streetlight or a blocked drain
  should have that reply within the hour."
- How rarely and unpredictably the work comes: "Constituents write through the contact form on my
  council page, a few a day, at no set times."
- What each run costs: "Each time the agent runs, it rereads my whole constituent file to see who
  has written before, which costs real money even when no new message has come in."
- The watching fact, which rules out a person: "Nobody on my staff can sit watching for new
  messages all day, since they come at no set times."

Why the other kinds fit worse:

- A person: messages come at no set times, so someone would have to watch for them all day, and
  the scenario says nobody on the staff can.
- A schedule: one slow enough to keep runs few (once or twice a day) leaves most replies hours past
  the hour; one frequent enough to meet the hour (every fifteen or thirty minutes) runs dozens of
  times a day for a few messages, and every one of those runs rereads the whole constituent file
  and costs real money, even when nothing is new.

Never accepted, by name: a person starting each run by hand when a message comes in (nobody can
watch all day); a schedule once or twice a day (too late for the hour); a schedule every few
minutes that runs the agent itself each time (dozens of costly runs that mostly find nothing).

The scenario does not say when the council office computer is on. An answer that assumes it is
never off is bringing in a fact from outside the scenario; see the activity's doesn't-show.

Irrelevant detail: "We started using the agent last spring."

Generic reasons that fail: "a schedule is automatic", "events are faster", "a person can make sure
it's done right".

True facts with no bearing on the choice, which also fail: the reply names the city office that
handles the problem; the council member represents the east side of town.

Examples of each kind of tied reason, for the event:

### q1

- **goal:** `c-choose-trigger`
- **cases:** event
- **answer:** An event: each new message through the contact form should start a run. Messages
  come a few a day at no set times and each should have a reply within the hour, so a slow
  schedule would be too late, a frequent one would mostly reread the costly constituent file for
  nothing, and nobody on the staff can watch for messages all day.
- **credit:** full when the answer chooses an event (including cheap repeated looks that start the
  agent only when a message is new) and gives a reason tied to this workflow of any of the three
  kinds: what makes an event good here, what would go wrong here without it, or what would make a
  specific other kind worse. One tied reason is enough, and a reason that also names what the
  event costs still earns full credit. A fact with no bearing on the choice (what the reply says,
  which side of town), one resting on the irrelevant detail, or one the facts contradict is not a
  tied reason. An answer listing two choices is ruled as choosing neither; a combined design is
  ruled by its main choice. Half when the answer chooses an event with a generic, untied or missing
  reason, or chooses a person or a schedule that runs the agent itself with a reason resting on a
  fact that bears on the choice (for example, a schedule every half hour "because replies are
  needed within the hour"). None when the choice is not accepted and the reason is generic, untied
  or missing, or no trigger is chosen.
- **tutor note:** if the answer picks a schedule every fifteen minutes to meet the hour, it read
  the deadline but missed the cost sentence; that is half. After the ruling, ask what each of those
  runs does when no message has come in.
