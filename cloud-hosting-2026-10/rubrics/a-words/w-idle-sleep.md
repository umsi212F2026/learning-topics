# Rubric: sleep

If the learner misses a question here, set a DEFINE or INTERPRET move for sleep live, as help (it
is recorded as helped and doesn't count), then come back to a production question.

Sleep is a free app being switched off while nobody is using it; the next request wakes it, after
a wait. The confusable is a crash, where the app stops because something went wrong. "Spin down"
and "scale to zero" mean the same as sleep and are not confusables.

### q1

- **goal:** `w-idle-sleep`
- **move:** DISTINGUISH
- **answer:** Sleep is the host switching the app off on purpose because nobody had used it for a
  while; nothing is wrong with it, and the next request wakes it, after a wait. A crash is the app
  stopping because something went wrong, usually an error in the code or its setup, and a visit
  doesn't fix that: it stays down, or keeps failing, until the cause is fixed.
- **credit:** full for the difference that matters: sleep is the host's doing, because of idleness,
  and a request wakes it; a crash is a failure, and a request doesn't cure it. Half for one side
  only. None for an incidental difference alone, such as that a crash is worse or that sleep is
  shorter.

### q2

- **goal:** `w-idle-sleep`
- **move:** CATCH
- **answer:** Sleep doesn't follow the clock. The app is switched off after a stretch with nobody
  using it, whatever the time of day, so it can sleep in the afternoon and stay awake past midnight
  if people are using it; and the next request wakes it.
- **credit:** full for naming that sleep follows a stretch with no visitors, not a time of day or
  the host switching off its servers. Half for "it's not on a schedule" without saying what
  triggers it. None for a different quibble alone, such as that hosts never switch off their
  servers, or that a paid plan doesn't sleep.
