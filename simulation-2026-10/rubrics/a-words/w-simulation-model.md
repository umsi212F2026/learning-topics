# Rubric: Simulation model

If the learner misses a question here, set a DEFINE or INTERPRET move for simulation model live, as
help (it is recorded as helped and doesn't count), then come back to a production question.

A simulation model is a simplified description of how a process works, precise enough for a
computer to run. It is not the real process it describes: it keeps only what its builders decided
matters and leaves the rest out, so what the model's rules say is a choice about the description,
not a fact about the world. And it is a description a computer can run, step by step: not a
physical mock-up, not a rule the real thing must obey, and not a loose remark too vague to run.

### catch-steady-wind

- **goal:** `w-simulation-model`
- **move:** CATCH
- **answer:** The steady wind is a simplification the team chose when they built the model, not a
  forecast of the real afternoon. The model is a description of how a fire spreads, not the fire,
  and the real wind can gust whatever the model's rules say; gusts are just what this model leaves
  out, so it can tell them nothing about gusts.
- **credit:** full for naming that the steady wind is something the model's builders chose to
  simplify or leave out, so it says nothing about what the real wind will do. Half for saying
  models can be wrong, or that real wind gusts, without saying the steady wind is a choice built
  into the description rather than a claim about the real fire. None for a different quibble
  alone, such as that the model needs more trials or should have chance in it.
- **tutor note:** if the learner says "the model is wrong about the wind", ask whether the model
  ever claimed anything about today's wind, or whether its builders simply left gusts out.

### vs-real-process

- **goal:** `w-simulation-model`
- **move:** DISTINGUISH
- **answer:** The model is a simplified description of the morning rush (people arrive in the
  lobby, press for floors, cars answer calls by set rules), written precisely enough for a
  computer to run. The real process is the actual elevators and people, with everything the model
  leaves out: someone holding a door, a car out for repair, a crowd arriving after a meeting. The
  model keeps only what its builders decided matters, so it can differ from what really happens.
- **credit:** full for naming that the model is a description of the process rather than the
  thing itself, and that it is simplified, leaving parts of the real process out; saying it is
  precise enough to run is welcome but not required. Half for only one of those, such as "the
  model is a computer version of it" with nothing on what it leaves out, or "the model is
  simpler" without saying it is a description rather than the thing. None for an
  incidental difference alone, such as that the model is cheaper or quicker to try changes on.

### catch-pick

- **goal:** `w-simulation-model`
- **move:** CATCH
- **type:** mcq
- **answer:** 4
- **credit:** full for 4 only. Choice 4 is a description of how the hall empties, precise enough
  for a computer to run. Choice 1 is a physical model of the building; nothing in it says how
  people move, and no computer runs it. Choice 2 is a rule the real hall must meet, not a
  description of how the audience leaves. Choice 3 is a fair observation, but as it stands it is
  far too vague to run: how many is "most", what the rest do, and how fast anyone walks.
- **tutor note:** a learner who picks 3 is close; ask what a computer would need to know before it
  could play out one evening from that sentence.
